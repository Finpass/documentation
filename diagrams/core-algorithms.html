Module 01 · Chatbot + RAG · one turn

From a question to a cited answer

The Go backend guards and enriches the request, the Python AI service retrieves, writes and checks. Three exits: a checked answer, source excerpts, or an honest not-found.

Core rules

  • Backend guards first: message 1-1000 chars, language id or en, compare list is empty or 2-4 products, 20 messages per user per minute (in-memory window).
  • The AI service gets profile facts, holdings, rule results and up to 5 news items. Name, email and phone never leave the backend.
  • Accepted when every [n] marker points to a real passage. An answer that says the sources do not cover it, with no markers, is also accepted: ungrounded, no citations.
  • One retry with the rejection reason in the prompt. A second rejection or an LLM error returns the top 3 excerpts with citations 1-3.
  • The disclaimer is appended by code and stripped from history, so the model never writes or copies it.
  • Short questions (under 5 words) borrow the previous user turn for retrieval, so a follow-up still has a topic.

Module 01 · Chatbot + RAG · retrieval

How the right passages are found

Dense retrieval from a Chroma index, filtered by metadata, then reranked by a cross-encoder. No keyword index and no rank fusion: the reranker does the precision work.

Core rules

  • Intent: a known 4-letter ticker, or company words without regulation words, means company filings; portfolio words search every source; regulation words search OJK rules; anything else is education.
  • Tickers come from the corpus metadata. When the question is about companies and no ticker is typed, the user's held tickers are used.
  • Years in the question (company intent only) trigger one search per year, k=50 split across the years, merged without repeats.
  • Every search filters on status approved and not expired, plus ticker, year and document type when known.
  • Rerank score is a sigmoid of the cross-encoder logit. Passages under 0.15 are dropped; the best 10 stay. With several years, each year keeps at least 2 first.
  • If fewer than 3 passages survive, the chat step adds up to 5 recent news items as extra numbered passages.

Module 01 · Chatbot + RAG · the index

How documents become searchable chunks

Chunking is the part that lives in the repo. Embedding and index building run offline; the app only downloads the finished index and refuses to start if it does not match.

Core rules

  • Sizes are in words because BGE-M3 sees about 1.4 tokens per Indonesian word. OJK regulation 320/40, OJK education 330/45, IDX statements 330/35 (size / overlap).
  • A heading line starts a new section. Every chunk carries its title and section, so a retrieved passage explains itself.
  • Pages are batched until about twice the chunk size, so a chunk can cross a page border and still reports its page range.
  • A page with three or more lines of 3+ numeric tokens is flagged as a table. A document with over 60% near-empty pages is flagged as scanned.
  • Startup compares the manifest's chromadb version and embedding model with the running ones. A mismatch stops the app.

Module 02 · AI service · profile explainer

Rules decide, the model only words it

The profile result is computed by rules. The model is allowed to rephrase it, and only if the text passes two checks; otherwise a fixed template is used.

Core rules

  • Submitting a profile never fails because of the AI: any error, invalid JSON or rejected text lands on the template.
  • Wording check: buy / sell words in Indonesian and English (beli, jual, buy, sell...), a few coin names, 4-capital-letter tickers and $TICKER are rejected.
  • Number check: every number in the text must equal a number in the facts. Indonesian and English separators (1.000.000, 3,5) are both understood.
  • The disclaimer is always added by code, whichever path produced the text.

Module 03 · Backend · profile rule engine

Questionnaire answers to a profile, ladder and health score

A pure function: no database, no AI. The same answers and previous profile always give the same result and the same trace.

Core rules

  • Matrix cells: C Conservative, M Moderate, A Aggressive. Bands are low below 40, medium 40-70, high above 70.
  • Consistency flag when |Q12 - Q13| is 2 or more (loss reaction vs. investment preference disagree).
  • Provisional profile when income is not shared: conservative assumptions, capped at Moderate, flagged to the user.
  • Health = average of Security, Safety, Growth, Wisdom, Freedom. Each is a weighted mix of lookup tiers.
  • Retake rule: 30 days cooldown and at most 3 assessments per rolling year.
  • Output also carries briefing priorities (emergency fund and debt for ladder 1-2, market news and macro otherwise) and data-sanity flags.

Module 04 · Backend · matching engine (portfolio)

Five rule layers from profile to a recommended portfolio

Rules choose and weigh every asset. The language model never picks products: it can only explain what this engine already decided.

Core rules

  • L1: base mix per profile (midpoints), then moves: horizon under 3 years lowers equity, freelancer or business owner moves 10 points to cash, 3+ dependents moves 5 points to fixed income, low knowledge removes crypto and small caps. Sharia swaps government bonds for sukuk.
  • Ladder 1-2 means no investing yet: only deposit 50, money-market fund 30, government bond 20 (sukuk if sharia), shown as instrument types.
  • L2 gates: sharia must be verified compliant; horizon under 3 years excludes high volatility (under 1 year also medium); Conservative excludes high volatility; knowledge none excludes crypto and small cap; basic excludes small cap.
  • L3: a cheap prerank decides which 20 assets per class get the full 7-part score. Missing data gives a neutral 50 (cost 70) and is written into the trace.
  • L4/L5: an asset is skipped if its daily returns correlate above 0.85 with one already picked (needs 30 shared days) or if its sector would pass 40% of the equity-like mix. Overflow above 10% per asset moves to others; what cannot be placed stays unallocated.
  • Ties break by score, then already held, then symbol, so output is deterministic. Compare (2-4 products) reuses the same gates and score; rank 1 is the best eligible fit.

Module 05 · Backend · matching engine (daily)

Four layers pick what goes in today's briefing

Each layer scores or filters on its own and writes a decision trace, so every item in a briefing can be explained afterwards.

Core rules

  • Alert thresholds by class: large cap 3%, mid/small 5%, global 3%, ETF 3%, fund 2%, gold 2%, crypto 5%. A per-holding threshold wins. Exactly equal does not trigger.
  • News: Conservative profiles drop high-volatility headlines and negative sentiment. Articles sent recently are skipped. The same topic three days in a row is deferred, or kept as a follow-up when nothing else qualifies.
  • News from low-tier sources never lets the briefing quote their numbers. Up to two extras (score 50+) feed the MORE reply.
  • Macro: BI rate matters to fixed-income holders, inflation to an emergency-fund goal, USD/IDR to foreign holdings (only if it moved over 2%), GDP to equity holders.
  • Nudge: health dimensions under 40 come first, then the ladder default. The same nudge is skipped after two days in a row.
  • Quiet market: no alert today or in the 5 previous recorded days.

Module 06 · Backend · WhatsApp briefing

Send once a day, obey every reply

Two loops share one contact record: a scheduler that sends the daily briefing exactly once, and a webhook that turns replies into state changes.

Core rules

  • Idempotent: one run row per user per local date, claimed with a single INSERT ... ON CONFLICT, so two ticks or two instances cannot send twice.
  • Send window: from the user's send time for 6 hours, in the user's timezone. Weekdays means Monday-Friday, weekly means Monday.
  • Message limit 800 characters. Data failure sends the nudge plus an apology; nothing to report sends a calm-market line plus the nudge.
  • A failed send retries up to 3 times, 5 minutes apart. Three failed days in a row raise a delivery issue in Settings.
  • Inbound: HMAC check, then groups, own messages and unknown numbers are ignored. A command is the whole message, case and punctuation ignored: MORE, STOP, RESUME, PROFILE, UPDATE, HELP, ENGLISH, INDONESIA.
  • Phone verification code: valid 10 minutes, 5 attempts, 60 seconds between codes.

Module 07 · Backend · dashboard

Totals, trend and allocation from one snapshot

The dashboard does arithmetic on valued holdings and the profile. The only text it adds is a fixed template.

Core rules

  • Total assets = liquid savings + investment value. With no holdings, the investment part is the amount the user self-reported.
  • Allocation floors each group to 0.1%, then hands leftover tenths to the largest remainders, so slices always sum to exactly 100.
  • YTD return = profit since 1 January divided by capital at the start of the year plus cost added since. Dividends are not included.
  • Idle cash counts toward total assets and weights only. Cost, profit and return describe the investments.
  • Fallback mix by profile if the matching engine fails: Conservative 15 stocks / 50 bonds / 35 cash, Moderate 50 / 35 / 15, Aggressive 70 / 20 / 10. Sharia uses sukuk and sharia stocks.

Module 08 · Backend · portfolio valuation

How one holding, then the whole portfolio, is valued

Valuation never invents a price. If a price or an exchange rate is missing, the holding is valued at cost and flagged as unvalued.

Core rules

  • Value = units × latest close × FX. For history, the FX rate is the one on or before each date (the last known rate if earlier).
  • Manual holdings (no ticker) use the manual price and date; they have no series.
  • A holding only enters history from its acquisition date. Dividends count only when the ex-date is on or after acquisition.
  • Sparkline: the last year of closes, downsampled to 30 points.
  • Totals report unvalued count so the screen can say how many positions are at cost.

Module 09 · Backend · market data classifier

Six labels for every asset, each with its rule

A deterministic classifier. Its labels (class, sharia, volatility, liquidity) are the inputs the matching gates rely on.

Core rules

  • Pure and deterministic: same input gives the same labels and the same trace order. Each step records its rule and an 'assumed' flag when a default stood in for missing data.
  • Volatility is the population standard deviation of daily returns over up to 252 days, times √252. Under 30 returns means unknown.
  • Liquidity overrides come first: deposit, money-market fund, gold, BTC and ETH are high; equity funds medium. Everything else uses average daily value in IDR.
  • IDX equity above Rp 10 trillion market cap is large cap, otherwise mid/small (also when no fundamentals exist, flagged as assumed). Non-IDX equity is global. A REIT name becomes property.
  • Sharia and sector come from a short curated list and a yfinance mapping. Anything else is unknown, never guessed, and the sharia gate then excludes it.
  • Each class carries its default alert threshold, reused by the daily alert layer.

Module 10 · Backend · discover

A precomputed screener table, read with keyset paging

Heavy math happens once in a refresh job. Search just reads one flat table, so every filter and sort is cheap.

Core rules

  • Refresh runs after market import and classification and swaps the table in one transaction; readers keep the old data until commit.
  • Valuation shows P/E when positive, else P/B, else P/S. Growth uses the latest two periods and needs a positive earlier value.
  • Dividend yield is capped: anything above 100% is treated as bad data and left empty.
  • Paging uses a keyset cursor (sort value + symbol), not an offset, so deep pages stay fast. A malformed cursor is rejected.
  • Per-user watchlist star and a 'watchlist only' filter sit on top of the same table.

Module 11 · Backend · news

Categorize once, flag per user

Articles are labeled when stored. Per-user relevance is a cheap lookup against held tickers at read time.

Core rules

  • Category: the channel decides when known; unclear channels fall back to title keywords; the last resort is global for non-Indonesian articles and macro for Indonesian ones. Four categories: capital markets, macro, global, real sector.
  • Relevant to holdings means any article ticker equals a held symbol, with the .JK suffix ignored on both sides (BBCA = BBCA.JK).
  • Bookmarks list is newest first (up to 200) and gets the same flags. Bookmarking an unknown article is rejected; repeating it is harmless.
  • The cursor is opaque but checked for shape, so a bad one is a 422, not a database error.

Module 12 · Backend · auth

Login, rotating refresh tokens and theft detection

Sessions are server-side rows keyed by a hash of the refresh token. Rotation makes a stolen token detectable.

Core rules

  • Unknown email and wrong password return the same error, and the unknown-email path still runs a bcrypt compare so response time does not leak which one it was.
  • Refresh tokens are 32 random bytes; only their SHA-256 is stored. Each refresh revokes the old row and creates a new one.
  • A rotated token reused within 10 seconds (two browser tabs) is tolerated. Later reuse is treated as theft and revokes every session of that user.
  • One-time codes: 6 digits, stored as SHA-256 of user | purpose | code, constant-time compare, consumed after use.
  • Google sign-in: by Google id; else by email, which links the account and marks it verified; else a new account.
  • Delete account asks for the password again when one exists, revokes all sessions, then cascade-deletes everything stored about the user.
